# FarMap Commercial MVP — Field Context Contract V1

## Boundary

Phase C introduces a server-owned field master and a read-only context projection. A `fieldId` is generated by the server in the form `field-<UUID>`. A legacy `location`/`farmlocation` row id, field name, display index, or label such as `A-12` is never promoted to canonical identity.

## APIs

All endpoints require the existing JWT boundary and resolve the actor from `BaseContext`.

| Method | Endpoint | Meaning |
| --- | --- | --- |
| GET | `/api/farms/{farmId}/fields` | List fields owned by the current user; an empty list is a valid `READY_EMPTY` result. |
| POST | `/api/farms/{farmId}/fields` | Create a minimum field record. The server generates `fieldId`, owner, status, source mode and timestamps. |
| GET | `/api/fields/{fieldId}` | Read a stable field record after farm ownership validation. |
| GET | `/api/fields/{fieldId}/context` | Assemble trusted farm, field, crop, location, weather, temperature, image, GIS, soil and satellite context. |

The create body accepts only `name`, `crop`, `area`, `growthStage`, `latitude` and `longitude`. The client cannot supply `fieldId`, `ownerUserId`, timestamps, source status or eligibility flags.

## Status and provenance

Every source has an explicit status. `READY` means a trusted value exists, `READY_EMPTY` means the source is connected but has no records, `UNAVAILABLE` means no provider or binding exists, `STALE` means the value is outside its freshness policy, and `DEMO` is reserved for an explicit demo session. API failure is not converted to `DEMO`.

Current real-data boundary:

- Farm and field master: `MYSQL`.
- Crop: field value when present, otherwise an explicitly labelled farm-scope crop/type.
- Location/GIS: field coordinates when present, otherwise farm centre with `scope=FARM`.
- Weather: current-month row from the existing MySQL weather table (`granularity=MONTHLY`); no random history is generated for REAL mode.
- Accumulated temperature: latest MySQL farm row when present.
- Images: `READY_EMPTY` farm-scope reference because `user_requests` has no trusted field relation; an upload is not a live camera.
- Soil and satellite: `UNAVAILABLE` until a real provider and binding are implemented.

## Security and compatibility

Farm ownership is checked before listing, creating, reading or assembling context. Cross-user access returns a closed error. Legacy location, crop and image rows remain readable through existing APIs; they are not guessed into field identities. Existing demo pages remain available only through the explicit demo session.

## AI request rule

For a real `field-*` request, Diagnosis and Agent endpoints use the server assembled context. Client weather, farm, crop, coordinates and source labels are overridden; when required weather is unavailable, Diagnosis fails closed instead of using client or demo weather.
