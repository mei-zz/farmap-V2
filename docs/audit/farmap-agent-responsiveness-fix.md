# FarMap Agent 响应与取消体验修复

日期：2026-09-22

## 根因

本次“长期停留在检索中，随后 Failed to fetch”不是 Milvus 查询本身持续阻塞。运行日志确认后端发生 `OutOfMemoryError: Metaspace`：旧启动参数把 Metaspace 限制为 80 MB，而服务稳定运行后的实际使用量约为 78 MB，继续加载 Spring MVC 类型时触顶，导致请求线程失败、SSE 连接中断。

普通 Copilot 问答此前还会进入大型随机回答模型池，响应时间随随机模型变化，不适合作为交互式聊天默认策略。

## 修复

- 本地启动默认调整为 `-Xmx512m -XX:MaxMetaspaceSize=256m -XX:MaxDirectMemorySize=128m`，仍允许外部环境覆盖。
- 百炼读取超时默认限制为 30 秒，单次模型路由最多尝试 2 个候选，避免多个慢失败串联。
- 普通 Copilot 流式回答设置 `force_fast`，使用已配置的百炼 `qwen-flash`；诊断和专家模型路由保持原策略。
- 浏览器聊天请求增加 45 秒总时限，到期后主动终止并给出明确提示。
- 发送期间按钮切换为红色“停止”；点击后中止当前浏览器请求、恢复输入状态，并显示“已停止生成”。
- 发送期间按 Enter 不再发起第二个并发请求，避免前后请求相互取消后出现误导性的网络错误。

## 验证

- 后端重新打包并启动成功，8080 正常监听。
- 前端 TypeScript 检查与 Vite 构建通过，5173 正常监听。
- Chrome E2E：`脆李有什么病虫害` 在 30 秒交互时限内完成，回答包含真实病虫害内容，且没有 `Failed to fetch`/服务不可用提示；单项回归总耗时 8.3 秒（含登录、切换农场和打开 Agent）。
- Chrome E2E：进行中的 SSE 请求可由“停止生成”按钮取消，界面恢复并显示取消反馈。
- 两项浏览器回归总耗时 13.0 秒，均通过。
- 修复后 JVM Metaspace 使用约 77.87 MB，上限 256 MB；未再出现 Metaspace OOM。
