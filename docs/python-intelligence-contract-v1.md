# FarMap Python Intelligence Contract v1

## Purpose

`ai.v1` is the narrow service contract between the Spring Boot Commercial Control Plane and the Python Intelligence Plane. Spring owns authentication, user/farm/field identity, evidence and diagnosis snapshots, agent actions, approvals, operations, outcomes, expert reviews, and audit records. Python owns inference and vector computation only. Python never creates business IDs, writes the FarMap business database, approves actions, or decides historical-case eligibility.

## Version and transport

- Contract version: `ai.v1`
- JSON over HTTP for control requests and responses.
- Internal calls carry `Authorization: Bearer <FARMAP_INTELLIGENCE_SERVICE_TOKEN>` when a service token is configured.
- `requestId` is generated by the caller when absent; `traceId` is propagated for diagnostics.
- Frontend code never calls Python directly.

## Tasks

The first contract keeps only three bounded task types:

| Task | Endpoint | Python output |
| --- | --- | --- |
| `VISION_ANALYZE` | `POST /v1/vision/analyze` | observation candidates and optional legacy analysis payload |
| `TEXT_EMBED` | `POST /v1/embeddings/text` | one 512-dimensional vector per input text |
| `IMAGE_EMBED` | `POST /v1/embeddings/image` | one 512-dimensional vector |

### Vision request

```json
{
  "contractVersion": "ai.v1",
  "requestId": "request-uuid",
  "traceId": "trace-uuid",
  "task": "VISION_ANALYZE",
  "images": [{"uri": "data:image/png;base64,..."}],
  "context": {"crop": "柑橘", "phenology": "幼果期"}
}
```

The v1 adapter accepts data URIs and HTTP(S) object references only when the hostname is explicitly present in `FARMAP_ALLOWED_IMAGE_HOSTS`. It rejects file/ftp schemes, loopback, link-local, private and reserved IP literals, localhost aliases, empty payloads, payloads over the configured 12 MB limit, and more than five images. Data URIs are decoded and size checked before the model call.

### Vision response

```json
{
  "contractVersion": "ai.v1",
  "requestId": "request-uuid",
  "traceId": "trace-uuid",
  "status": "SUCCEEDED",
  "model": "hunyuan-turbos-vision",
  "observations": [{"kind": "VISION_ANALYSIS", "content": {}, "confidence": 0.8}],
  "warnings": [],
  "latencyMs": 1200,
  "analysis": {}
}
```

`observations` are candidates. Spring is responsible for normalising them into stable Evidence IDs and persisting the immutable Diagnosis snapshot. The adapter does not emit `diagnosisId`, `recommendationId`, approval IDs, or operation IDs.

### Embedding requests and responses

Text:

```json
{
  "contractVersion": "ai.v1",
  "requestId": "request-uuid",
  "traceId": "trace-uuid",
  "task": "TEXT_EMBED",
  "texts": ["柑橘叶片黄化"]
}
```

Image uses the same envelope with `task: IMAGE_EMBED` and an `image` base64/data URI string. Successful responses include `contractVersion`, `requestId`, `status: SUCCEEDED`, `model`, `dimension: 512`, vector values, and `latencyMs`. The Java gateway rejects a versioned response whose dimension is not exactly 512 with `AI_CONTRACT_INVALID`.

## Health and capabilities

`GET /v1/health` distinguishes process readiness from model readiness. The status vocabulary is `READY`, `DEGRADED`, and `UNAVAILABLE`; one unavailable capability does not hide healthy capabilities. `GET /v1/capabilities` lists supported tasks and endpoint paths. A missing Hunyuan key therefore leaves the Flask process reachable and reports vision `UNAVAILABLE` rather than crashing the process or returning fabricated analysis.

## Error envelope

```json
{
  "contractVersion": "ai.v1",
  "requestId": "request-uuid",
  "status": "FAILED",
  "error": {
    "code": "AI_MODEL_UNAVAILABLE",
    "message": "vision model is not configured",
    "requestId": "request-uuid",
    "retryable": true
  }
}
```

Supported codes are `AI_INVALID_REQUEST`, `AI_IMAGE_INVALID`, `AI_IMAGE_FETCH_BLOCKED`, `AI_MODEL_UNAVAILABLE`, `AI_MODEL_TIMEOUT`, `AI_EMBEDDING_FAILED`, `AI_CONTRACT_INVALID`, `AI_AUTH_REQUIRED`, and `AI_INTERNAL_ERROR`. Java maps transport failures to typed `IntelligenceGatewayException`; unavailable or invalid responses are never converted to an empty successful result.

## Authentication and logging

The internal service token is read from `FARMAP_INTELLIGENCE_SERVICE_TOKEN`; no production token is hard-coded. Local scripts may opt into `FARMAP_INTELLIGENCE_ALLOW_UNAUTHENTICATED_LOCAL=true` for a developer-only process. Logs and health payloads may include request/trace IDs, task, status, model label, and latency. They must not include API keys, JWTs, raw image content, or private prompts.

## Compatibility boundary

The Flask `/analyze` and Local AI `/embedding/*` endpoints remain for legacy callers. New commercial calls use `/v1/*` through the Java `IntelligenceGateway`. Legacy routes do not define the commercial contract and are not allowed to create business records or historical cases.
